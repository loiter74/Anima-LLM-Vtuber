# 验证 Animetta

让 `tooling.quality` 成为测试选择的唯一真相源，避免重复门禁。

## 流程

1. 读取目标文件附近的 `AGENTS.md`，列出本次任务实际修改的精确文件路径；传给 `--paths` 的每一项必须是文件，不得传目录。
2. 在 Windows 首次验证前运行 Python 3.13 断言；不可用时立即停止。
3. 在运行宽泛目标测试前，先用 `tooling.quality plan --tier affected --paths <精确路径...>` 只生成计划；复用同一份路径清单完成最终验证，不用 `--worktree` 混入用户改动。
4. 若计划出现未知路径、错误命中 Docker 或日常改动选择 `backend-full`，先判断是映射错误还是任务确实触及高风险配置；修正映射后重新规划。若 `backend-full` 确属必要，不再手工运行它已覆盖的宽泛测试，只保留实现期间最小回归用例。
5. 冻结差异前，先对本轮 Python 文件运行 Ruff 格式化；有前端文件时，对本轮前端文件运行 Prettier 写入，再执行 `git diff --check`。不得把格式检查留到耗时门禁之后。
6. 差异冻结后只运行一条 affected 规范入口。规划器已经覆盖的目标测试不得重复运行；格式或类型问题修正后仅复跑对应检查，除非改动改变了运行语义。
7. 报告冻结计划、选中组、缓存来源、耗时和失败证据；不得把未执行项写成通过。

## 约束

- 日常通道固定使用 affected，并传入当前任务的精确文件路径，不得用目录代替。
- 大型跨域任务必须先 plan 后 verify；禁止“多轮宽泛专项测试 → backend-full/affected 再全跑”的重复路径。
- `quick` 只用于定位，不能与最终 affected 串行重复。
- `quality validate` 只用于质量目录、模型或映射结构变更。
- `full`、shadow、benchmark 和实时 Docker 只用于对应的高风险或发布需求。
- 文档、普通单测和 Skill 验证不加载 Playwright；界面或浏览器证据变化时才使用 `$qa-testing-playwright`。
- 格式化、换行或生成元数据等语义不变修正，只复跑对应检查。

## 输出

只给出验证结论、实际运行命令、选中测试组、耗时和最小失败信息。
