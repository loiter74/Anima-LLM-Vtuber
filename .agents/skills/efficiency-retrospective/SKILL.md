# 执行效率反思

复盘当前任务中本可避免的路径，并消除它再次发生的原因。不要总结任务内容或重新审查代码质量。

## 成本契约

- 默认不启动子 Agent、不重新执行测试、不全仓扫描。
- 不重新读取当前上下文已有的文件，不为统计数据重复执行命令。
- 优先使用本轮已有的工具调用、错误、搜索、修改、测试和最终成功路径。
- 仅在准备固化规则时做少量定向搜索，确认是否已有同义规则。
- 现有证据足够时直接反思。

## 工作流

1. **还原路径**：只记录影响效率的关键节点。
   - 实际路径：`开始 → 尝试 → 失败或绕路 → 修正 → 成功`。
   - 最短可行路径：`开始 → 必要检查 → 正确修改 → 必要验证 → 完成`。
   - 不得把任务开始时不可能知道的信息假设为已知。
2. **定位浪费**：只检查路径错误、工具错误、信息获取过量、验证过量、调试绕路、规则缺失或错误。忽略正常且必要的步骤。
3. **追到根因**：从表面现象继续归因到缺少稳定项目事实、路径映射、明确边界、能力索引或确定性脚本，验证映射错误，Skill 过重，指令重复或冲突，或单次偶发问题。
4. **选择改进**：默认只处理一个最高收益问题。判断这个问题是编码bug还是流程固定除非，仅当两个问题相互独立且都会明显复发时，最多处理两个。依次优先消除整条错误路径、避免重复失败、减少重复搜索、减少不必要验证、减少上下文读取。
5. **正确固化**：按问题性质选择一个位置；无法证明会缩短未来路径时不固化。

| 位置 | 适用内容 |
| --- | --- |
| 最近的 `AGENTS.md` | 稳定的项目事实、入口、禁止路径、环境限制或不变量 |
| 已有 Skill | 可重复的判断或工作流；优先修改已有 Skill，不新增重复能力 |
| Script / Tool | 路径发现、状态采集、比较、环境检查、固定转换等确定性操作 |
| 测试 / 质量映射 | 错误的测试选择或影响范围判断 |
| 不固化 | 一次性外部故障、临时环境异常、低复发概率或纯个人偏好 |

6. **简化规则**：先定向搜索同义规则，依次优先修正错误、收紧模糊、合并重复，最后才新增。规则必须给出能改变下次动作的条件和动作，不写泛泛提醒。
7. **低成本验证**：只确认改进能阻止主要浪费路径复发，且没有引入更复杂的新流程。除非改动本身要求，否则不运行项目完整验证。

## 停止条件

找到最高成本的可避免路径及其根因，并固化一个直接改进或确认无需固化后立即结束。继续分析只能发现次要问题时停止，不处理所有历史效率问题。

## 输出

仅报告：

**浪费路径**：本轮最主要的可避免步骤。

**根因**：导致该路径出现的项目级或流程级原因。

**固化**：修改了什么规则、Skill、脚本或映射；无必要则写“无”。

**下次路径**：类似任务下一次应采用的最短执行路径。
